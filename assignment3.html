ASSIGNMENT 3 - FINAL PROJECT

FocusScape

An evolving soundscape for focused study.

01 - Project Synopsis

FocusScape is a browser-based interactive soundscape designed to support students during independent study. It combines different ambient sound layers to create a personalised background environment.

Instead of playing one fixed recording, FocusScape allows users to adjust the balance of sounds and generate small variations. The aim is to create a calm listening experience that can change without becoming distracting.

02 - Design Scenario

The project responds to the experience of students who study independently and want background audio to help them focus. Some students prefer a particular atmosphere, while others want more control over individual sounds.

The design challenge was to create a browser-based audio interface that supports personalisation while remaining simple enough to use during a study session.

How the Final Project Responds

The final version combines quick atmosphere presets with individual volume controls. Users can begin with a preset and then adjust the sound layers to suit their preferences.

A New Variation button introduces small random changes, allowing the soundscape to evolve when the user chooses. The interface also displays feedback to help users understand which sound levels have changed.

This approach balances ease of use, personal control and variation while keeping the main purpose focused on studying.

04 - Core Interactive Features

Atmosphere Presets

Three presets - Rainy Study, Café Focus and Quiet Focus - allow users to select a starting atmosphere quickly. Each preset applies a different balance of the four sound layers.

This feature was developed from Prototype 02, which explored a simpler alternative to adjusting every sound individually.

Individual Sound Controls

Four sliders allow users to adjust Rain, Café, Wind and Tone independently. Percentage labels show the current values, while the audio responds to adjustments during playback.

This feature builds on Prototype 01 and allows users to personalise a preset rather than being limited to fixed sound combinations.

New Variation

The New Variation button generates small changes to the current sound mix. Instead of replacing every setting with a completely new combination, it changes the existing values within limited ranges.

This builds on the randomisation experiments in Prototypes 04 and 05. The final design uses user-triggered changes so students can decide when they want a different soundscape.

Variation Feedback

After a new variation is generated, the interface displays which sound layers increased, decreased or remained unchanged.

This feature develops Prototype 06 by connecting the changes in the audio with visible information.

Playback Controls

Users can start and stop the soundscape through a main playback button. The interface displays the current session state so users can understand whether audio is playing.

05 - Extended Technique: Math.random()

My chosen extended technique is JavaScript's Math.random(). It is used to generate controlled variation in the soundscape.

A helper function converts random numbers into values within a defined range. When the user selects New Variation, the program adds a small random amount to each current sound level. 

function randomRange(min, max) {
  return Math.floor(
    Math.random() * (max - min + 1)
  ) + min;
}

mix.rain = clamp(
  mix.rain + randomRange(-8, 8)
);

The values are limited using a clamp function so the sound levels remain within the allowed range. The updated values are then displayed on screen and applied to the audio system.

I chose controlled randomisation rather than completely unpredictable changes because FocusScape is intended for studying. The soundscape should feel less repetitive without suddenly changing into a very different atmosphere.

06 - Design System

Visual Style

FocusScape uses a minimal visual style with a light neutral background, dark typography, subtle borders and rounded interface elements. The aim is to create a calm and readable experience.

Information Hierarchy

The main playback control is presented prominently, followed by atmosphere presets, variation controls and individual sound adjustments. This structure supports both quick setup and more detailed personalisation.

Interaction and Feedback

Buttons use clear labels, sliders display numerical values and the session status communicates playback state. Variation feedback explains the result of user-triggered randomisation.

Responsive Layout

The layout adapts to different screen sizes so the controls remain accessible on desktop and smaller devices.

07 - Peer Testing and Final Decisions

During Assignment 2, I collected feedback from seven participants on six parallel prototypes.

All seven participants described the amount of control in the information design prototypes as "about right". For randomisation, three preferred automatic variation, three preferred manual variation and one preferred variation with visible feedback.

Several participants preferred the simplicity of atmosphere presets, while others valued detailed control over individual sounds. One participant suggested combining presets with individual controls. Another recommended combining visual feedback with individual sound adjustments.

These comments influenced the final design, which brings together presets, sliders and variation feedback rather than selecting only one prototype.

Testing also identified limitations. Some participants found the feedback logs distracting, while others reported that changes were too subtle or different noise layers were difficult to distinguish. These findings informed the areas I considered during final refinement.

08 - Development and Commit Logs

Development from Assignment 2 to the Final Project

Assignment 2 explored six parallel prototypes across two design directions: how users control the soundscape and how random variation is introduced. The final project combines their strengths based on peer feedback and the requirements of the study scenario.

Iteration 01 - Presets and Individual Controls

Prototype 01 explored individual sound controls, while Prototype 02 explored atmosphere presets. Peer feedback highlighted the convenience of presets but also the value of detailed personalisation. The final version combines three presets with four independent sliders, allowing users to start quickly and then adjust their sound mix.

Iteration 02 - Controlled Randomisation

Prototypes 04-06 explored different approaches to variation. Three participants preferred automatic variation, three preferred manual variation and one preferred visible feedback. I retained user-triggered variation so students can choose when the soundscape changes.

I also refined the JavaScript so that Math.random() generates small changes relative to the current mix, rather than replacing all values with a completely new combination. A clamp function keeps the resulting values within the permitted range.

Iteration 03 - Audio and Interface Synchronisation

The final JavaScript connects the presets, sliders and variation button to the same sound mix. The Web Audio API manages the sound layers and their gain values. The displayed percentages are updated alongside the audio settings, helping users understand their current configuration.

Iteration 04 - Variation Feedback

Prototype 06 introduced visible feedback. Some participants found this useful, while others considered the logs distracting or the changes difficult to notice.

The final version retains feedback indicating which sound levels increased, decreased or remained unchanged. This connects the randomisation technique to visible information without requiring users to interpret the sound alone.

Iteration 05 - Visual and Responsive Refinement

The final interface uses a neutral colour palette, clear typography, rounded controls and a more structured hierarchy. Playback is presented first, followed by presets, variation and detailed sound controls. This supports quick setup while keeping further personalisation available.

Technical Decisions and Limitations

Implementation and Design Rationale

Instead of generating a completely new sound mix each time, I used Math.random() to create small adjustments around the current values. Each sound layer has a different adjustment range: Rain (+/-8), Cafe (+/-7), Wind (+/-6) and Tone (+/-5). These smaller ranges were chosen to reduce sudden changes that could interrupt concentration. A clamp function keeps the values between 0 and 100.

I also connected the presets, individual sliders and variation button to the same JavaScript mix object. This means that changes made through different controls remain consistent. The updateAudioVolumes() function applies the new values to the Web Audio API, while updateDisplay() updates the visible percentages. This approach avoids conflicting settings and makes the interface easier to understand.

Math.random() was selected to create controlled variation, while the Web Audio API supports browser-based sound generation and individual volume adjustment. The design aims to maintain a consistent listening experience during study.

However, synthesised audio may sound less natural than environmental recordings. Testing also suggested that some changes are too subtle to notice and that detailed feedback may interrupt concentration. These remain opportunities for future improvement.
